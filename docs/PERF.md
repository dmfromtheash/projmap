# Замер производительности окна

`tools/perf/run.mjs` запускает опубликованный `projmap.exe` в режиме `--test` с CDP-портом и **своей** папкой состояния
(`PROJMAP_HOME`, по умолчанию `%PROJMAP_SCRATCH%\perf-home`), поэтому открытое окно владельца не мешает и не меняется.
Окно — только на не основном дисплее; если подключён один экран (ноутбук) — на нём. Прямоугольник окна проверяется
каждую секунду, при выходе на основной дисплей процесс закрывается.

```powershell
$s = '<папка для временных файлов>'
dotnet publish src/ProjMap.App/ProjMap.App.csproj -c Release -r win-x64 --self-contained false -o "$s\app" --artifacts-path "$s\build"
$env:PROJMAP_SCRATCH = $s
node tools/perf/run.mjs --exe "$s\app\projmap.exe" --root <репозиторий> --runs 3 --label after
#   --only files,classes   только эти сценарии     --profile classes   CPU-профиль (.cpuprofile + топ функций)
```

Сценарии: «Модули», «Папки», «Файлы» на весь проект, «Классы» модуля «Ядро», «Файл: SceneRenderer.cs», «План»,
«Подробное древо», выбор блока, раскрыть/свернуть «Ядро». Для каждого: время раскладки и до картинки, **блокировка**
(самый долгий кадр перехода), FPS и худший кадр при перетаскивании и зуме колесом (CDP-ввод, rAF + long tasks),
**чёткость холста** (пикселей холста на пиксель экрана, 1.0 = полное разрешение), пик JS-памяти, время фонового скана,
предупреждения консоли. Итог — медианы в `perf.md` / `perf.json`, плюс снимки «целиком» и «150 %».

Цели: FPS ≥ 58, худший кадр < 50 мс, блокировка < 200 мс, чёткость 1.0.

`tools/perf/lab.mjs --script <эксперимент.mjs>` — то же окно для разовых опытов (модуль получает `app` с `ev`, `send`,
`settle`). Так найдены причины в таблице ниже.

## Что тормозило и как исправлено (2026-10-29, Map: 1403 файла, 118 тыс. связей)

| Причина (замер) | Исправление |
|---|---|
| `pixelRatio: 1` при масштабе Windows 125 % — холст в 0,8 разрешения, мыло | `pixelRatio: 'auto'` |
| Новый уровень добавлялся, потом весь перестилизовывался после раскладки; первая отрисовка 1100 блоков — 300–500 мс одним куском | раскладка до показа, показ частями по кадрам с подбором размера части (`swapIn`) |
| Затемнение при выборе меняло класс у ~2000 элементов (210–260 мс) | «вуаль»: один полупрозрачный узел поверх, поднимаются только оставленные элементы |
| 1600 стрелок в Cytoscape — 75 % кадра при начале/конце жеста | слой стрелок `edgelayer.js`: свой холст, штрихи пачками по цвету, векторные при зуме |
| ELK кладёт маршруты вложенных стрелок в `children[].edges` — читался только корень, 2/3 стрелок рисовались кривыми | маршруты собираются со всех уровней |
| Подсветка 782 входящих связей с подписями при выборе «Ядра» (зум 9 FPS) | подсвечиваются 120 сильнейших |
| Вид «Файл»: подсветка 4000 строк кода одним куском, 1400 скрытых стрелок | код дорисовывается частями; лишние стрелки добавляются только для выбранной функции |
| `text-max-width: -4` у рамок — 4500 предупреждений в консоли | ширина подписи не меньше 20 |
| WebGL-режим Cytoscape 3.31 | не подходит: рисует сегментные стрелки кривыми, нет пунктира, спрайты мылятся при приближении |
