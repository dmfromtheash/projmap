2. **Ярусы v1** по плану Astra: правила (встроенные + `.projmap/views.rules.json`), назначение файлов с объяснением

   (для Map: Core ни от кого не зависит). Раздел `views` в graph.json (все три сериализатора). Тесты.
3. Вид в окне по выбору владельца; затем «Функции» (из документов, имён и кнопок) и «История» (этапы, недели, «что затронул R13»
   — у R13 22 пути по двум коммитам).
4. Проверить на Map и минимум одном другом проекте (`C:\Projects\DiscordBots\ensi-bot` — там фронтенд/сервер/бот/БД).
   Perf: сценарии `tools/perf` + новые «ярусы × функции», «переключение недель», «срез от кнопки».
5. Astra (по «да»): независимая проверка классификации ярусов на 2–3 проектах; ревью кода видов.

## Правила
- Владельцу — только по-русски, просто; у вопроса — что смотреть, где и зачем.
- **Экран не брать под контроль**: окна не выводить вперёд, скриншоты не делать, пока владелец сам не попросит; проверки — фоном
  (CLI, e2e/perf со своим `PROJMAP_HOME`), результаты — страницами-артефактами.
- Данные владельца не трогать (`%LOCALAPPDATA%\projmap` с его «Недавними», его окна). Сканы — с `-o` вне проекта.
- Коммиты в projmap — по ходу, с понятными сообщениями; в Map ничего не менять без поручения.
- Убирать за собой временные файлы.
